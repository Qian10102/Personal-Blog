# 复习计划

入口：`/review-planner/`。沿用现有 Supabase 私人邮箱准入与会话。界面随站点语言、主题切换，任务正文保留用户原文；AI 草稿默认中文。

## 使用流程

1. 在“时间设置”填写 IANA 时区、学期第一周的星期一、学期结束日、计划开始日。日期时间均按这个时区解释；默认单次 50 分钟、间隔 10 分钟。
2. 在“课程表”添加每次课程，或下载专用模板再导入。科目按名称归并，适用周次如 `1-8,10-16`，单双周按学期周次计算。停课关联原课程与具体日期；补课填写具体日期、科目和时间。
3. 添加考试，填写起止时间、范围及掌握程度。同一科目可建多场考试。
4. 手动建立任务，或点击“AI 拆分任务”。AI 草稿可编辑标题、内容、阶段、顺序与估时，删除不需要的项；确认时可替换未开始的任务或追加，已有完成记录的任务保留。请自行核对重复内容。
5. 设置每周可用时段、每日上限及临时占用，并勾选确认。添加或删除每周时段后需要重新确认。
6. 生成计划，查看容量与未排入内容，确认后才替换当前版本。清单按时段勾选，完成记录会同步。漏做的任务须手动点击重排，再预览确认。

## 导入模板

支持 `.xlsx`、UTF-8 `.csv`，上限 2 MB、500 条课程；Excel 读取第一个工作表。列名依次为 `科目,星期,开始时间,结束时间,周次,单双周`，保留中文列名。星期填 `1–7`（也接受周一等），时间填 `HH:mm`，单双周填 `全部/单周/双周`（也接受 `all/odd/even`）。Excel 原生时间单元格可读取。

预览支持直接修正单元格，校验通过并确认前不会保存任何课程。导入追加课程，跳过与当前课表完全一致的课程；文件内部重复行会显示错误。带逗号的周次在 CSV 中应加双引号，推荐使用 Excel 另存为 CSV 自动处理转义。

## 排程约定

- 只安排从计划开始日与当前时刻中较晚者起的时间；规划跨度最多一年。
- 每周可用时段先合并，再扣除课程、考试、临时占用、已完成时段；重叠占用不会重复扣减。可用时间不足时保留缺口，不增加每日上限。
- 每次分配按“剩余同阶段用时 × 掌握权重 ÷ 截止前剩余可用时间”计算优先级。薄弱／一般／熟练权重为 1.5／1／0.75，同分按截止时间、任务 ID 排序。
- 每场考试先完成所有知识梳理，再完成练习；每阶段按顺序执行。主体任务截止于考前一天零点，回顾只排在考前一天，且须在主体任务完成后开始。时间不足时分别报告未排入内容。
- 任务估时以 25 分钟为单位。默认每段最多 50 分钟，短段至少 25 分钟；可用时段间已有的空隙计入休息。已完成内容保留原始内容、时间及用时，未完成旧时段不会占用新计划容量。
- 夏令时跳变中不存在或有歧义的本地时刻会被拒绝，需修改相应时段。内部时段使用 UTC 时间戳，界面使用计划指定的时区。

## 数据和接口

`review_planners` 保存一份原子更新的 JSON 输入文档与修订号；`review_plan_versions` 保存每次确认的不可变快照；`review_completions` 保存完成时段快照。`private.review_planner_writes` 仅保存请求标识及载荷摘要，用于重试去重。

客户端通过 `get_review_planner()` 获取完整状态，通过 `save_review_planner(p_request_id, p_expected_revision, p_document, p_plan?, p_completion?)` 保存。事务检查修订号，拒绝旧设备覆盖；同请求重试不重复写入。版本快照包含输入原文、时段与缺口，新版本必须保留全部完成快照。客户端不能直接写表。

保存结果未确认时按账号将待提交载荷放在当前标签页的 `sessionStorage`，可用原请求 ID 重试。冲突时保留输入并停止编辑，支持下载输入备份后重新加载。浏览器禁用存储时，本页仍可重试，刷新会丢失尚未确认的输入。备份用于保留与人工恢复，首版没有 JSON 备份导入功能。

Edge Function `review-task-breakdown` 接收 `{examId, expectedRevision}`。服务端校验 JWT 和授权邮箱，按调用者 RLS 读取保存的考试范围；返回 `{tasks, warnings}`，不写任务或日程。输入不发送整张课表或空闲时间。前后端共用任务结构校验。范围上限 12,000 字符、草稿最多 80 项；不自动重试收费调用。

## 配置和发布

1. 应用 `supabase/migrations/20261103142006_review_planner.sql`，在测试账号下运行 `tests/sql/review-planner.sql`；脚本最终回滚。此文件版本号与已应用的云端迁移对齐。
2. 部署 `supabase/functions/review-task-breakdown/index.ts`，包含同目录 `handler.ts`、`deno.json` 和 `../_shared/review-task-draft.ts`。保持 `verify_jwt = true`。
3. 在 Supabase Dashboard → Edge Functions → Secrets 添加 `DEEPSEEK_API_KEY`。可选 `REVIEW_AI_MODEL`，默认 `deepseek-flash`。密钥不得写入 `PUBLIC_*`、前端、构建产物或仓库。
4. 登录复用已有 `/vocabulary/` 回调，完成后自动返回 `/review-planner/`。同一浏览器通过 30 分钟有效的一次性返回标记恢复入口；禁用存储或换设备打开邮件时，登录后可从导航进入复习计划。生产及本地 `/vocabulary/` 回调沿用 README 中既有配置。
5. 运行 `npm test`、`npm run build`，沿用现有 GitHub Actions／腾讯云发布方式发布静态前端。

模型调用采用 DeepSeek JSON Output、非思考模式、输出最多 8,192 token、超时 80 秒。余额不足、超时、限流、空白输出或格式错误均不写入任务，现有输入保留，可手动填写或主动重试。普通排程与重排无需模型。

按 2026-11-03 的官方价格，每次输入 2,000、输出 3,000 token 约为 0.014–0.028 元；实际受用量与高峰时段影响，Supabase 按现有套餐计算用量。[DeepSeek 官方计费](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)、[JSON 输出](https://api-docs.deepseek.com/zh-cn/guides/json_mode/)、[Supabase 函数认证](https://supabase.com/docs/guides/functions/auth)。

## 验证

`npm test` 包含课程周次、单双周、停补课、冲突合并、每日上限、休息、任务阶段和截止时间、缺口、重排保留完成快照、时区与夏令时、Excel／CSV、AI 认证与故障测试。`tests/sql/review-planner.sql` 验证原子确认、幂等重试、并发修订冲突、完成快照保留与访问权限，所有写入回滚。上线还需在实际账号下验证邮件回调与付费模型调用。
